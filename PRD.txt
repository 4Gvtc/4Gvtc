PRD – ENHANCED RIDE-SHARING APP
Version 1.0 · Juillet 2026 · Web app (Vite + React 19 + TypeScript)
1. Résumé
Application web de VTC premium, thème sombre avec accents néon (vert #1ae86a, jaune #f5e642). Refactorisation d'un prototype monolithique (App.tsx, 1318 lignes) vers une architecture modulaire prête pour la production, avec intégrations Google Maps et Stripe en mode mock/stub, drop-in ready pour clés live.
2. Objectifs
? Transformer le code monolithique en architecture modulaire (types, lib, data, integrations, features, hooks)
? Livrer un produit déployable, pas un prototype
? Couches d'intégration réelles (Maps, Stripe) avec providers mock, remplaçables par de vraies clés API
? Respecter un standard de design élevé (Taste_Skill.md) sur toute l'interface
3. Utilisateurs cibles
? Passager : réserve, suit et paie une course
? Conducteur (dashboard prévu) : gère ses courses et ses statistiques

7. Architecture cible
? types/ — types de domaine
? lib/ — utilitaires (id, format, constants, fare)
? data/ — données mock par domaine
? integrations/ — maps, stripe (types + mockProvider par service)
? features/ — modules fonctionnels (scheduling, chat, dashboard...)
? hooks/ — logique réutilisable
? components/ — décomposition de l'ancien App.tsx
8. Contraintes non-fonctionnelles
? Code prêt production, pas de placeholders creux
? Intégrations = vraies couches d'abstraction avec mock providers interchangeables
? Qualité de design gouvernée par Taste_Skill.md, appliquée dès le départ
? Livraison progressive : architecture ? data/utils ? intégrations ? features ? polish UI
9. Risques
? Bug thème clair/sombre non résolu (valeurs CSS dupliquées)
? Volume de features restantes important : prioriser par valeur produit
